This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Code Ocean capsule that builds an Ubuntu-desktop Cloud Workstation image running the IBL Ephys
Alignment GUI. No application code here.

- `code/run` is a no-op (`exit 0`). There is no Reproducible-Run path; all behavior is in
  `environment/postInstall`, which runs at image build time.
- The GUI is a separate repo, installed by `postInstall` at a pinned commit:
  <https://github.com/AllenNeuralDynamics/ibl-ephys-alignment-gui>
- Capsule 6044160. Inputs: output of capsule 0325751 plus the subject's stitched SmartSPIM asset,
  attached as data assets.

## Code Ocean basics

A capsule is a git repo built into a Docker image, marked by `.codeocean/`. It runs headless via
`code/run` or as an interactive Cloud Workstation; only the workstation mode matters here.

| Path | Access | Lifetime |
|---|---|---|
| `/code` | read-write | The repo |
| `/data` | read-only | Mounted data assets, one subdirectory each |
| `/results` | read-write | Only persistent output location for a run |
| `/scratch` | read-write | Persists across runs; not mounted in pipelines |
| `/root`, `/tmp` | read-write | ~5 GB cap; use `/scratch` for large files |

Image layers (`/opt`, `/opt/conda`, `/usr/local/bin`) reset to their baked state when a workstation
is stopped and resumed. Only `/scratch`, `/results` and `/code` persist.

A capsule is not a Python package. `uv` is the dependency tool. Runs are headless, no stdin.
`.codeocean/secrets.json` holds references, not values.

## Do not hand-edit the Dockerfile

`environment/Dockerfile` is generated by the Code Ocean UI from `.codeocean/environment.json`
(hence its `# hash:sha256:` header). Editing it breaks the UI environment editor. Change the
environment through:

- `environment/postInstall` — anything scripted. Safe to edit directly.
- The Code Ocean Environment tab — base image, apt packages, container `ENV`. The UI rewrites
  `environment.json` and the Dockerfile together, so do not hand-edit either alone.

Exception: when `.codeocean/environment.json` is absent the capsule is in custom-Dockerfile mode and
the Dockerfile is the source of truth. That file is present here, so the rule applies.

The header is sha256 of the Dockerfile minus the header line:
`tail -n +2 environment/Dockerfile | sha256sum`.

## Validating

No tests, lint config, or build step. Full validation is a rebuild plus a workstation session.
Locally: `bash -n environment/postInstall` and `shellcheck environment/postInstall`.

Wrapper scripts are quoted here-docs inside `postInstall`, so `bash -n` does not check them.
Extract one to a temp file to check it.

## Environment variables

Read by the GUI (GUI repo, under `src/ephys_alignment_gui/`: `core/settings.py`, `core/timing.py`,
`io/datapackage_loader.py`, `io/docdb.py`):

| Variable | Meaning |
|---|---|
| `EPHYS_ALIGNMENT_INPUT_ROOT` | Default root of the input file browser |
| `EPHYS_ALIGNMENT_OUTPUT_ROOT` | Where saved alignments are written |
| `IBL_ASSET_ROOTS` | `os.pathsep`-separated asset search roots for the datapackage loader |
| `EPHYS_ALIGNMENT_GUI_TIMING` | Enables timing instrumentation |
| `username` | Curator recorded on docdb-saved alignments; blank skips docdb writes |

They can be set in two places, but only one of them reaches the GUI:

1. Dockerfile `ENV` / `environment.json` `env_variables` — clobbered by the lightdm/guacamole
   session, which PAM builds without inheriting the container's `ENV`. Since `code/run` is a no-op,
   nothing else in this capsule reads them either, so they have no effect at all. Changeable only
   through the Code Ocean UI.
2. `/etc/environment`, appended by `postInstall` — the single source for these defaults, and what
   the GUI actually reads.

Keep it that way: do not add a fallback copy of a default in a wrapper script or a debug config.
The copies drift, and the one that loses is silent about it.

`username` is prompted once via zenity and cached in `/scratch/.ibl-gui-username`.

## Desktop launchers

`postInstall` writes each `.desktop` entry to three places: `/root/.config/autostart` (session
login), `/usr/share/applications` (app menu), `/root/Desktop` (icon).

- Entries run `gnome-terminal -- bash -c "…; exec bash"`. The trailing `exec bash` keeps the
  terminal open after the GUI exits or crashes; `gnome-terminal` has no portable `--hold`.
- That `bash -c` is non-interactive and skips conda's `profile.d`, so `/opt/conda/bin` is off PATH.
  Hence `ln -sf "$(command -v launch)" /usr/local/bin/launch`.
- `trust-desktop-launchers` marks icons trusted so they don't prompt on first click. It runs as an
  autostart entry, not at build time, because `gio set` needs a session-time gvfs/dbus daemon.
